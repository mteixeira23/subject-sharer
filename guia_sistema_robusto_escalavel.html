Fase 1: 0% a 10% - Concepção, Requisitos & Modelagem DDD

Construir um sistema robusto começa antes de qualquer linha de código. O maior erro em engenharia de software é iniciar o desenvolvimento sem alinhar o modelo de domínio com as regras de negócio.

1.1 Entrevista de Arquitetura com Antigravity (Slash Command /grill-me)

Inicie a fase 0 acionando a entrevista de arquitetura para resolver ambiguidades, regras de permissão e volume de dados esperado:

📌 Perguntas Fundamentais de Arquitetura
  • Volume de Dados: Quantos usuários simultâneos e registros por segundo o sistema atenderá?
  • Consistência: O sistema exige consistência ACID estrita (ex: financeiro) ou consistência eventual (ex: redes sociais)?
  • Multi-Tenancy: Os dados serão isolados por empresa/cliente (Tenant ID) ou é uma base de usuário único?

1.2 Modelagem de Domínio & Esquema Relacional

Desenhe as entidades centrais utilizando relacionamentos de chave estrangeira (Foreign Keys), tipos de dados estritos (UUID, TIMESTAMP WITH TIME ZONE, DECIMAL para dinheiro) e restrições de integridade (UNIQUE, NOT NULL, CHECK).

Fase 2: 10% a 20% - Repositório, Regras & Antigravity Setup

Estabeleça a estrutura do projeto com regras de desenvolvimento automáticas salvas no repositório.

2.1 Arquivo AGENTS.md do Repositório

Crie na raiz do seu projeto o arquivo de regras permanentes que orientará o Antigravity em todas as refatorações:

# Diretrizes Rígidas do Sistema

## Stack Tecnológica
- Frontend: React 18 + Vite + TypeScript (strict mode).
- Backend / Database: PostgreSQL no Supabase com Row Level Security (RLS).
- Cache & Estado Server-Side: React Query (@tanstack/react-query).

## Regras Invioláveis de Código
1. Proibido utilizar 'any' no TypeScript. Defina interfaces exatas em src/types.
2. Todas as mutações no banco devem invalidar explicitamente as chaves de cache do React Query.
3. Após qualquer edição, sempre execute:
   - npx tsc --noEmit (verificação de tipos)
   - npm run build (compilação de produção)
4. Trate todos os erros assíncronos com try/catch e exiba notificações Sonner amigáveis.

Fase 3: 20% a 35% - Banco de Dados Relacional, Migrações & RLS

O banco de dados é o coração do seu sistema. Para um sistema escalável, aplique o versionamento rigoroso de código SQL via migrações e isolamento de segurança por linha (Row Level Security - RLS).

3.1 Exemplo de Migração SQL Versionada com RLS (Supabase/Postgres)

-- Migration: 20260813_init_schema.sql

-- 1. Criar Tabela de Clientes
CREATE TABLE public.clients (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  email TEXT UNIQUE NOT NULL,
  balance NUMERIC(15, 2) DEFAULT 0.00 NOT NULL,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW() NOT NULL
);

-- 2. Criar Índices de Alta Performance (B-Tree)
CREATE INDEX idx_clients_user_id ON public.clients(user_id);
CREATE INDEX idx_clients_email ON public.clients(email);

-- 3. Habilitar Row Level Security (RLS)
ALTER TABLE public.clients ENABLE ROW LEVEL SECURITY;

-- 4. Criar Política Rígida: Usuário só lê seus próprios dados
CREATE POLICY "Users can read own clients" 
ON public.clients 
FOR SELECT 
USING (auth.uid() = user_id);

-- 5. Criar Política Rígida: Usuário só insere dados para seu próprio user_id
CREATE POLICY "Users can insert own clients" 
ON public.clients 
FOR INSERT 
WITH CHECK (auth.uid() = user_id);

Fase 4: 35% a 50% - Design System, UI/UX & Componentização

Sistemas robustos utilizam um Design System atômico, baseado em componentes desacoplados e previsíveis.

4.1 Estrutura de Componentes Primitivos

  • UI Primitives (Radix UI / Shadcn): Utilização de componentes primitivos acessíveis (Dialog, Popover, Select, Dropdown) sem reacessar o DOM diretamente.
  • Tokens HSL de Cores: Suporte nativo a temas Light/Dark via CSS Variables HSL.
  • Tratamento de Estados Visuais: Skeleton screens durante o carregamento (isLoading), telas vazias (empty states) e capturadores de erro (ErrorBoundary).

Fase 5: 50% a 65% - Camada de Dados, Cache Server-Side & Estado

Para escalar sem travar a interface do usuário, desacople o estado local (UI) do estado de servidor (Server-Side State).

5.1 Gerenciamento de Estado com React Query

// Custom Hook para busca de dados com cache inteligente
import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query';
import { supabase } from '@/integrations/supabase/client';

export function useClients(userId: string) {
  const queryClient = useQueryClient();

  // Fetching com Cache e Invalidação Reativa
  const { data: clients = [], isLoading } = useQuery({
    queryKey: ['clients', userId],
    queryFn: async () => {
      const { data, error } = await supabase.from('clients').select('*');
      if (error) throw error;
      return data;
    },
    staleTime: 1000 * 60 * 5, // Dados válidos por 5 minutos
    enabled: !!userId,
  });

  // Mutação Otimista (Optimistic Update)
  const addClientMutation = useMutation({
    mutationFn: async (newClient: { name: string; email: string }) => {
      const { data, error } = await supabase.from('clients').insert([newClient]).select().single();
      if (error) throw error;
      return data;
    },
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['clients', userId] });
    },
  });

  return { clients, isLoading, addClient: addClientMutation.mutateAsync };
}

Fase 6: 65% a 75% - Autenticação, Autorização (RBAC) & OWASP

🛡️ Protocolo de Segurança de Aplicação
  • Autenticação JWT: Armazenamento seguro de sessões com expiração e refresh tokens automáticos.
  • Controle de Acesso por Papel (RBAC): Verificação em duas camadas: rotas protegidas no frontend e tabelas user_roles com RLS no banco.
  • Higienização de Entradas: Validação de schemas via Zod para impedir SQL Injection e XSS.

Fase 7: 75% a 85% - Integração de APIs, WebSockets & Resiliência

Sistemas distribuídos devem tratar falhas de rede de forma graciosa:

  • Comunicação em Tempo Real: Assinaturas WebSockets para atualizações instantâneas sem necessidade de F5.
  • Resiliência de Rede: Algoritmos de Exponential Backoff com jitter e Circuit Breakers para evitar sobrecarga nas APIs externas.

Fase 8: 85% a 92% - Testes Automatizados & Core Web Vitals

Garantia de qualidade antes de publicar em produção:

  • Testes Estáticos de Tipagem: Execução do compilador TypeScript (npx tsc --noEmit).
  • Testes E2E (End-to-End): Automação de fluxos do usuário via Playwright ou Chrome DevTools MCP.
  • Auditoria de Performance: Verificação de métricas Core Web Vitals (LCP < 2.5s, INP < 200ms, CLS < 0.1).

Fase 9 & 10: 92% a 100% - CI/CD, Deploy & Manutenção Autônoma
