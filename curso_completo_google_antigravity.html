1. Módulo 1: Introdução & Arquitetura Agentic Coding

📌 O que é o Google Antigravity?
O Google Antigravity (AGY) é uma plataforma de desenvolvimento autônomo orientada a agentes. Diferente de chats passivos, o Antigravity possui acesso direto ao sistema de arquivos local, terminal do sistema operacional, subagentes paralelos e ferramentas de teste/inspeção visual em tempo real.

1.1 Assistente Tradicional vs. Antigravity Agentic Engine

Recurso Assistentes de Chat Comuns Google Antigravity (AGY)
Autonomia Responde trechos isolados de texto Lê, edita, compila e valida o código no disco
Verificação Humano precisa copiar, colar e testar Executa suítes de testes (`npm test`, `pytest`) autônomas
Multiprocessamento Monolítico e sequencial Orquestra múltiplos subagentes simultâneos
Conectividade Restrito ao texto digitado Chrome DevTools MCP, Bancos de Dados, Terminais

2. Módulo 2: O Fluxo de Pair Programming & Ferramentas do Sistema

O Pair Programming com o Antigravity exige uma postura baseada em rigor técnico e evidência empírica:

  • Nunca Adivinhar Código ou Estrutura: O agente inspeciona os arquivos relevantes do projeto antes de propor edições.
  • Diagnóstico Baseado em Logs Reais: Diante de erros de build, a primeira ação é ler a pilha de erro completa e não truncada.
  • Preservação de Contratos de API: Edições em assinaturas de funções exigem a atualização de todas as chamadas no repositório.

2.1 Os Artefatos de Transparência

Para manter o desenvolvedor no controle total, o Antigravity gera dois documentos dinâmicos:

  • implementation_plan.md: Plano técnico com metas, análise de risco, lista de arquivos criados/editados e plano de testes.
  • walkthrough.md: Resumo detalhado do trabalho concluído com evidências e testes executados.

3. Módulo 3: Slash Commands & Modos Avançados de Trabalho

Os Slash Commands são atalhos para ativar fluxos inteligentes na plataforma:

/grill-me     -> Entrevista interativa de arquitetura
/goal         -> Ativa modo de execução autônoma ininterrupta
/learn        -> Grava novos padrões e regras aprendidas na sessão
/schedule     -> Configura temporizadores ou agendamentos cron
/browser      -> Inicia automação e testes visuais no navegador

4. Módulo 4: Sistema de Customizações (Rules, Skills & Plugins)

O Antigravity permite moldar o comportamento da I.A. através de arquivos Markdown declarativos:

4.1 Exemplo de Arquivo de Regras (AGENTS.md ou rules/*.md)

# Diretrizes do Repositório

- **Linguagem**: TypeScript com modo estrito habilitado (`strict: true`).
- **Validação**: Execute `npx tsc --noEmit` após modificações estruturais.
- **Segurança**: Nunca faça commit de chaves API ou credenciais de produção.

4.2 Exemplo de `SKILL.md` (Manual Técnico Reutilizável)

---
name: deploy-firebase
description: Guia de compilação e publicação de aplicações no Firebase Hosting.
---

# Procedimento de Deploy

1. Garanta que as dependências foram instaladas: `npm install`.
2. Gere o pacote de produção: `npm run build`.
3. Publique no Firebase: `npx -y firebase-tools@latest deploy --only hosting`.

5. Módulo 5: Protocolo MCP & Orquestração de Subagentes

Com o **Model Context Protocol (MCP)**, o Antigravity conecta-se ao DevTools do Chrome, BigQuery e serviços de banco de dados para inspecionar métricas em tempo de execução e auditar acessibilidade.

💡 Dica de Orquestração
Use o comando de subagentes para disparar tarefas simultâneas: enquanto um subagente analisa um log de erro extenso, o agente principal continua implementando a interface.

6. Módulo 6: Antigravity SDK em Python & Automação CI/CD

Para automação em pipelines de servidores de integração contínua sem interface gráfica, o SDK em Python oferece controle completo:

from antigravity import AgentSession, TaskGoal

session = AgentSession(workspace_path="./meu-projeto")

goal = TaskGoal(
    instruction="Auditar todos os componentes e verificar cobertura de testes unitários",
    auto_approve_edits=True
)

result = session.execute(goal)
print(f"Status do Agente: {result.status}")

7. Módulo 7: Troubleshooting & Prevenção de Perda de Dados

⚠️ Regra de Segurança Rígida
Comandos irreversíveis de remoção de dados (DROP TABLE, TRUNCATE, rm -rf em produção) exigem obrigatoriamente confirmação explícita do desenvolvedor antes de serem executados.

Checklist de Verificação Diária

  • [ ] Inspeção do repositório antes de grandes refatorações.
  • [ ] Verificação do plano de testes em implementation_plan.md.
  • [ ] Execução autônoma do comando de build (npm run build / `pytest`).
  • [ ] Gravação de novos aprendizados com o comando /learn.
